## 2. P0致命问题

### P0-1：PCT runner直接target leakage

`build_windows_faithful()`构造：

```python
seg_p = pw[i:i + WINDOW_SIZE]
X.append([..., seg_p, ...])
Y.append(pw[i + WINDOW_SIZE - 1])
```

即`Y`正是输入`seg_p`的最后一个元素。模型并未预测未来，而是在输入包含target的情况下回归当前值。所有RMSE与constraint/unconstrained比较都受到标签泄漏污染。

**关闭条件**：输入结束于`t`，target严格为`t+1:t+145`；加入索引级单元测试，断言`max(input_timestamp)<min(target_timestamp)`。

### P0-2：伪144步horizon

runner常量写`TIME_AHEAD=144`，但模型`d_out=1`，`Y`也是单值，报告仍输出`horizon=144`。这不是近似144步，而是单步任务被错误标注为144步。

**关闭条件**：输出shape为`(B,144)`，target为未来144步向量，loss和JS按论文协议处理全部forecast horizon；否则报告必须写`one-step diagnostic`，不得称结构对齐。

### P0-3：epochs参数未生效且结果标签错误

`run()`内部循环使用全局`EPOCHS=100`，没有接收`args.epochs`；主程序却在输出中打印`args.epochs=20`。因此当前六行“20 epochs”结果实际训练100 epoch。

**关闭条件**：将epochs显式传入`run()`并在manifest同时记录requested/actual epochs；用epoch计数断言或history行数验证。

### P0-4：PCT输入语义仍非官方结构

第三输入通道被人为定义为`(wind/15)^2`，不是官方表格中index 4的真实forecast/feature语义；私有江苏数据、pitch angle和原预处理仍缺失。因此当前最多是shape-aligned toy transfer，不能称structure-faithful。

### P0-5：PI-TFN物理项存在W/kW单位错配

代码计算：

```python
p_phys = 0.5 * rho * area * cp * wind**3 / p_rated
```

空气动力公式输出瓦特，而Kelmarsh `p_rated`约11,469（数据单位kW）。缺少`/1000`会把per-unit physics target放大约1000倍。fixed-Cp RMSE≈87–89及“+128115%”主要是单位错误的机械后果，不是错误先验或约束冲突的科学发现。

**关闭条件**：明确所有单位；先转成kW再除以kW rated，或rated使用W；用已知风速/面积手算单元测试。

### P0-6：PI-TFN仍不能称paper-spec

即使修复mask和Cp上界，当前仍只有简化BiLSTM+Cp head，缺多尺度注意力、热状态GRU、叶片模块及论文真实输入；rotor area采用6×Senvion MM92假设而非论文参数。`paper-spec`命名应改为`PI-TFN-inspired loss reconstruction`。在单位修复和公式逐式核验前，第二方法族结论冻结。

### P0-7：PCT显著性存在伪重复

报告以3个seed×2个架构形成n=6 Wilcoxon。相同seed、相同数据在两个架构下不是六个独立重复；架构是实验因素，seed嵌套于架构。将六格当独立样本得到p=0.0312属于pseudoreplication。

**关闭条件**：每个架构独立≥5–9 seeds；用分层/重复测量模型或按架构分别检验，再做跨架构meta/interaction分析。

### P0-8：PRISMA flow仍不闭合

当前flow：89 identified→72 assessed→26 coded→21 final included。若最终纳入21，则abstract/full-text阶段应有51篇排除并逐类给出理由；现仅列出编码后的5篇排除，缺失其余46篇的审查ledger。Web-search 17篇与OpenAlex 72篇之间也未证明完成跨通道去重。

**关闭条件**：为89条记录建立唯一ID与逐条screening decision，精确报告每阶段排除数及理由；最终所有统计只基于21篇纳入语料。

### P0-9：文献统计仍混用26篇与21篇

最终纳入集排除5篇后，D5应为18/21 `none-reported`、1/21 `ablation-absent`、2/21 `harm-quantified`；D4应为20/21 `no-code`、1/21 `code-mismatch`。MASTER/编码报告仍使用24/26或25/26，包含已排除论文。

## 3. 五份独立审稿意见

### EIC

论文方向较上一轮更成熟：约束来源、生命周期、实现忠实度和伤害报告的联合审计具有潜在领域价值。但新提交的两项“硬证据”都被基础实现错误击穿，说明研究治理仍未达到终审水平。建议拒绝当前研究包，修复后以完整manuscript重投，而不是继续在报告间累积结论。

评分：重要性7/10；当前创新6/10；完成度3/10；Decision Reject。

### Reviewer 1：系统综述与编码

真人coder_C使证据质量明显提高，且如实报告D1–D3中等κ是优点。但低κ意味着taxonomy仍需训练样例和更清晰decision tree；不能只在仲裁后报告漂亮分布。PRISMA flow尚缺46篇排除记录，最终分析又混用21和26作为分母。现阶段只能称scoping/systematic pilot audit。

评分：透明度4/5；系统性2/5；Decision Major/Reject。

### Reviewer 2：ML复现与统计

PCT代码静态核查仍有价值，尤其是paper/code divergence。但所谓faithful runner存在target leakage、虚假horizon标签和epochs标签错误；n=6统计又将架构格当独立样本。下游结果全部需要作废重跑。gradient matching是有用诊断，但还缺lambda tuning和gradient direction。

评分：静态审计4/5；下游实验1/5；统计2/5；Decision Reject。

### Reviewer 3：风电物理与第二方法族

PI-TFN的W/kW错配足以解释fixed-Cp爆炸。learned Cp head可能仅通过输出极小Cp来补偿单位错误，从而使所谓paper-spec结果也失去物理解释。使用假定的六台MM92面积可以做sensitivity，但不能称论文参数或忠实方法重建。第二家族尚未建立。

评分：物理有效性1/5；外部效度2/5；Decision Reject。

### Devil's Advocate

作者的新结论仍可能完全由实现错误产生：PCT“144步忠实实验”实际把target放进输入、只预测一个点，并把100 epochs打印成20；PI-TFN“错误先验爆炸”则来自瓦特除以千瓦。显著性来自将架构格当独立样本和在单位错配数据上增加seed。若修复这些问题，两个方法族的负收益可能显著缩小、消失或反转。因此当前不能声称跨族审计成立。

**CRITICAL：新增PCT与PI-TFN结果必须整体INVALIDATE。**
