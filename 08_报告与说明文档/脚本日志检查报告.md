## 三、日志记录机制分析

### 3.1 主日志系统 (`run_all.sh`)
主脚本`run_all.sh`实现了完善的日志记录机制：

```bash
# 主要特性:
1. 创建日志目录: mkdir -p logs
2. 时间戳命名: TIMESTAMP=$(date +%Y%m%d_%H%M%S)
3. 主日志文件: MAIN_LOG="logs/run_all_${TIMESTAMP}.log"
4. 每个脚本独立日志: local log_file="logs/${script_name%.py}_${TIMESTAMP}.log"
5. 双重记录: 同时输出到屏幕和日志文件 (tee命令)
6. 错误处理: 记录失败脚本的退出码和最后10行日志
```

### 3.2 Python脚本日志方式
检查了代表性的Python脚本，发现：

1. **无标准logging模块**: 所有脚本均未使用Python的`logging`模块
2. **使用print语句**: 所有输出通过`print()`函数实现
3. **部分脚本有进度输出**: 使用`print(f"进度: {i}/{total}")`等形式
4. **输出重定向**: 通过`run_all.sh`的tee机制捕获所有输出

### 3.3 日志命名规范
日志文件命名遵循以下模式：
- 根目录: `{脚本名}_output.log`
- logs目录: `{脚本名}_{时间戳}.log`
- 错误日志: `{脚本名}_error_{时间戳}.log`
