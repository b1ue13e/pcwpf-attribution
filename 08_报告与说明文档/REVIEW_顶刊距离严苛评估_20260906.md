## 二、与一区的距离：四道结构性硬门槛

### 门槛 1（P0，一票否决级）：v4 双人编码不存在

- 第五轮 P0-3 的关闭条件是"至少另一名编码者用相同全文材料、相同 schema v4 独立编码，
  再算 inter-rater κ/α"。当前状态：46 篇的 D1–D3、D4、D5 四字段、ablation_type
  **全部只有杜老师一人**的全文级判定。
- F1 使问题更严重：`48项语料最终验收结论.md` 把"预编 vs 全文级 0 变动"写进验收，
  但预编者也即全文级编码者本人——**这是 intra-rater，且是同一次判断的两个时间切片，
  连 v3→v4 那种 schema 变更下的稳定性都不算**。
- 一区审稿人的标准杀法："All headline statistics rest on a single annotator's judgment.
  Table X must be accompanied by inter-rater reliability on the final corpus, or the
  claims must be downgraded to a pilot."
- **关闭成本**：真人第二编码员对 46 篇做 D4+D5（事实性字段，摘要+检索级，约 1 天）+
  ablation_type 复编（需方法节，约 1–2 天）；D1–D3 可抽样 20 篇复编。κ/α 按 5 字段分别报告。

### 门槛 2（P0）：C2 的两个支柱发现需要过"平凡性"检验

- **0/46 负面报告**：Devil's advocate 的杀法是——"positive-result publication bias 在所有
  ML 应用领域都成立，风电物理约束有何特殊？"当前稿件层面没有回答。要过一区，必须把它从
  "普遍的发表偏倚观察"升级为"领域特异的伤害机制"：物理约束是**硬编码的错则必伤**组件，
  其错误在调度层有**可量化的经济代价**（弃风、备用考核、过充惩罚），而这正是 D5 第二字段
  `harm_metric_reported = 0/48` 已经铺好的路——但需要一个**示范性的 harm 量化实验**把
  闭环跑通（见路径 A）。
- **46/46 代码不可核验**：注意它与 C3 构成的逻辑张力——全语料只有 1 个可执行案例，
  fidelity 维度的"领域结论"实际是"45/46 无从审计 + 1/46 失实"。一区会要求把 D4 表述
  从"不可核验"推进到"不可核验**意味着什么**"（例如：不可复现的结果应被视为未证实的
  工程声称），否则只是图书馆学统计。
- **52.2% 真隔离消融**：三个发现里最新、最有张力，但同样是单人编码，且
  module-ablation vs constraint-on-off 的边界判定（both 类 8 篇如何计入）需要
  预注册规则 + 独立复编，否则是第二个 18/19/20 口径漂移的温床。

### 门槛 3（P1）：C3 贡献量撑不起一区级第三贡献，且被 C2 结构性锁死

- 静态 reverse-JS 差异是全文最硬的单点证据（Task A 独立验证），但第五轮 P0-8 已判：
  去掉作废的 RMSE 幅度后，它只是"一个代码库的一处 divergence orientation mismatch"。
- **结构性死结**：C2 已证明全语料只有 PCT 有公开代码——所以"第二个同深度 static audit
  案例"在现有语料内**不可能存在**。唯一出路是**自己重建**：选 2–3 个代表族
  （training-loss 族 22 篇 / inference-architecture 族 22 篇各取 1–2 篇高引），
  做 paper-spec reference implementation 并公开，把审计从"找到 1 个有代码的"
  变成"对无代码领域提供首批参考实现 + 在其上跑 prior-substitution stress test"。
  这既补 C3 广度，又顺手把 46/46 not-found 从"坏消息"变成"我们的动机"。
- **成本**：2–4 周工程 + GPU（算力现成且全闲，见 F3）。这是在跑实验与一区之间
  真正的瓶颈，不是算力。

### 门槛 4（P1）：训练实证层统计功效不足且无独立重跑

- 现有最好结果：错误先验 +123.7%（n=5，t 显著、Wilcoxon 边界）；"n=5"在一区
  等于"试点规模"。主线自己的纪律已把它们降级为附录线索——这是对的，但也意味着
  **论文当前没有任何达到一区统计标准的训练实验**。
- PI-TFN p=0.0625 恰好卡在边界外，审稿人会写 "underpowered"。
- 升级到一区形态需要：≥10 seed × ≥2 站点 × 预注册协议 + 第二人独立实现重跑
  （第四轮已指出"我做不了"——这是人力问题，不是技术问题）。

### 附加门槛（P2）：PRISMA 通道与 manuscript

- 检索仅 OpenAlex title.search + web search 两通道；一区 systematic audit 惯例要求
  Scopus / WoS / IEEE Xplore 至少其一的正式检索记录 + 完整 flow diagram。
- 完整稿件不存在（F6）。所有终审模拟都是在"没有稿件"的状态下游行——
  **当前最被低估的风险是：写出来之后数字口径、表间一致性会再爆一轮**
  （旧方法论文 8/31 报告的 P0-1 数据完整性问题就是这个项目的前科）。

## 四、通往一区的路径（按性价比排序）

### 路径 A（性价比最高，2–3 周）：守住 audit 定位，补"harm 量化闭环"

1. 真人第二编码员完成 v4 双人编码（门槛 1）——**不做这个，以下都白做**。
2. **Harm 量化示范实验**（用闲置算力，1 周）：在 Kelmarsh/Penmanshiel 上用现有
   v4 runner，把"错误先验 +123.7% RMSE"翻译成调度语言——接 8/31 报告里的铜板界面，
   算弃风率/备用缺额/考核罚款（M CNY），写成"本文是第一个把约束伤害量化到
   系统层的"——这直接回应 0/46 的平凡性质疑，把 D5 从"别人没报告"升级为
   "我们演示了该怎么报告"。这是从二区跨到一区的**关键一跳**。
3. 补 Scopus/WoS 检索通道，重画 PRISMA flow。
4. 写完整 manuscript（Methods=Protocol v2，Results=46 篇三发现 + harm 量化示范，
   C3 作 static case box，治理记录进 Supplementary）。

### 路径 B（决定上限，+2–4 周）：自建参考实现，解开 C3 死结

- 对 training-loss 族和 inference-architecture 族各选 1 篇高引 no-code 论文做
  paper-spec 重建并开源，跑 prior-substitution stress test。C3 从 1 案例变 3 案例，
  同时产出领域首个参考实现库（独立可引用的软件贡献）。

### 路径 C（退路）：二区定位立即写稿

- 只做门槛 1（双人编码）+ 写稿，投 scoping audit 定位的二区。1–2 周可投。
- 代价：0/46 + 52.2% 的发现张力被浪费在较低档位。

### 明确不建议

- ❌ 复活旧方法论文线（FG-MoE/Ultra-LSNT）：9/1 归因诊断已自我证明载体、动机、
  测试季三重缺陷，救它等于重写一篇论文。
- ❌ 在双人编码完成前写任何"领域比例"数字进摘要。
- ❌ 把训练实验重新升级为正文 claim（n=5 天花板封死）。
