## 结论先行

**数据是次要矛盾。** 真正的掉点是四个因素的复合：
载体选弱 > 腐蚀挑战太温和（动机不成立）> 评估指标错位 > 测试季太温和（头部风险被低估）。
其中"数据问题"真实存在，但正确的修法不是"换数据"，而是"换载体 + 换动机 + 补季节 + 重做 guardrail 机制"。

---

## 实验1：载体归因（同数据、同划分、同协议）

canonical 80/20 实测（Ultra-LSNT vs iTransformer）：

| 层面 | iTransformer | Ultra-LSNT | 差值 |
| :--- | :--- | :--- | :--- |
| raw（同一 base checkpoint）| R²=0.9314 | R²=0.9161 | **−1.5 点** |
| full_guardrail（5 seeds, mean±std）| R²=0.9555±0.0006 | R²=0.9311±0.0010 | **−2.4 点** |

**判定：载体明显选弱。** 换载体（iTransformer 为主载体）+2.4 点，这是当前所有可选项中收益最大的一步；同时拆掉审稿人"为什么用更慢更差的模型"的必杀问题。

**附带发现（已定位根因，非 bug 而是协议选择）**：raw 与 clip_only 变体的 5 个 seed 预测 MD5 完全相同（ultra `03a0d0a2eae7`、itransformer `a7fed91e7a`），full_guardrail 的 5 seeds 各不同（`c80fa1ba71`…）。根因：`run_pi_moe_full_training_evidence.py` 中 `args.seed` 只传给 `train_pi_moe_full(..., seed=args.seed)`，base 模型统一加载 `--base-checkpoint checkpoints_ts/main/best_model.pth`（与 seed 无关）。因此：
- raw / clip_only 的 std=0 是**真实的**（它们就是同一个 base），论文可如实写"single base checkpoint"，但**不得**包装成"5-seed 种子稳定性"；
- full_guardrail 的 5-seed ±std 是真实的（FG 微调随机性生效）。
- 若想报 base 模型的真实种子方差，需新增 `--base-train-seeds` 单独训练 5 个 base（当前 canonical 归档没有这一步）。

## 实验2：腐化归因（train-time 注入后 val 掉点）

从训练日志最后 epoch 的 clean_mse vs corr_mse：

| 模型 | 掉点范围 | 中位掉点 |
| :--- | :--- | :--- |
| iTransformer | 15% ~ 318% | ~16% |
| Ultra-LSNT | 8% ~ 158% | ~65% |

**判定：腐蚀对两者同样存在，Ultra-LSNT 并不更稳。** 论文"Ultra-LSNT 更抗腐蚀"的核心叙事在 canonical 协议下没有体现，"抗腐蚀"不是好卖点。原因：corruption 是合成注入（Gaussian+drift+quant+flatline/spike/dropout），挑战温和。

## 实验3：插补归因（先修数据 vs 直接吃脏数据）

服务器 `results/supplementary_evidence/missingness_imputation_ultra_dlinear_summary.csv` 实测：

| 配置 | R² |
| :--- | :--- |
| ffill + DLinear（missing 0.1）| **0.9326** |
| ffill + Ultra-LSNT（missing 0.1）| 0.8718 |
| ffill + DLinear（missing 0.3）| **0.9242** |
| ffill + Ultra-LSNT（missing 0.3）| 0.8692 |

**判定：动机不成立。** "直接吃脏数据"比"先插补+简单模型"差 6 个点，且插补管线是最便宜的工业标准做法。必须正面回答"为什么不先修数据"，否则 motivation 被反向利用。

## 实验4：季节归因（训练/测试季节错配）

| 数据集 | 春 | 夏 | 秋 | 冬 |
| :--- | :--- | :--- | :--- | :--- |
| 训练（97,222）| 10,366 | 25,912 | 34,138 | 26,806 |
| 测试（24,306）| 18,835 | 5,471 | 0 | **0** |

冬季 power mean=71,073、std=36,730（全年最高出力/最高波动季），**测试集完全不含冬季**。
测试期 = 春（78%）+ 初夏（22%），是最温和的季节。

**判定：头部风险被系统性低估。** 训练丰富、测试欺软——审稿人必问"冬季高风速段表现如何"。修法：补冬季/高风速季数据，或明确把"仅暖季验证"写进摘要级 limitation（现在只是简介里一笔带过）。

## 综合归因表（掉点贡献的定性排序）

| 因素 | 贡献 | 证据 | 修法成本 |
| :--- | :--- | :--- | :--- |
| 载体选弱（Ultra-LSNT vs iTransformer）| ★★★★ | 实验1 −2.4 点 | 低（换主载体）|
| 腐蚀挑战太温和 → 动机不成立 | ★★★ | 实验2 掉点中位 16%/65%，实验3 插补+6 点 | 中（改动机或换真实故障协议）|
| 测试季太温和 → 头部风险低估 | ★★★ | 实验4 无冬秋 | 中（补数据）|
| guardrail 机制脆弱（11 手工系数、λ₂ 敏感）| ★★ | 审查报告 P0（λ₂=1.0 时 R² 崩 0.38）| 高（重做机制 = 唯一大的创新点）|
| 评估指标错位（平均 R² vs 爬坡/尾部/成本）| ★★ | 审查报告 P0-7（Ramp F1 0.35 vs 0.59）| 低（换指标进正文）|

## 破局决策建议（按证据支撑排序）

1. **立即做（0 成本）**：iTransformer 提为并列主载体，Ultra-LSNT 降为 deployment profiling 对象。
2. **立即做（0 成本）**：「插补+强模型」正面写进正文，回答"为什么不先修数据"；能赢就进主表，赢不了就改动机（在线不允许等完整窗口 / 插补平滑偏差在调度层有害，需调度实验证明）。
3. **立即做（低）**：指标升级——Ramp F1、P95|e|、CRPS、缺额成本进正文；把"仅暖季验证"写进 limitation。
4. **短期（中）**：补冬季/高风速季数据（或第二站点标定迁移演示），把测试季缺陷补上。
5. **中期（高，唯一大创新点）**：重做 guardrail——干掉 11 个手工系数的 v^proxy，换在线标定 power-curve 包络 + conformal 可行区间 + decision-aware 惩罚；λ₂ 自适应。
6. **同步（P0 数据完整性）**：修复 seed 可复现性（5-seed base 模型真实训练），单一 manifest 自动生成全表，清掉所有孤儿数字。
