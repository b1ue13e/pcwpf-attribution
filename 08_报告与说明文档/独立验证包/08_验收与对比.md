## 一致原则

验证者的任务是**给出自己的判断**，不是复现我们的答案。对比的目标是：
- 一致 → 结论增强；
- 不一致 → 以"更严格/更有依据"的一方为准改写结论，或标记为开放问题。

**任何情况下都不许"说服验证者改答案"**。分歧是产出，不是错误。

## Task A 验收（reverse-JS 方向）

对比对象：验证者报告 vs 下述我们当前的记录。
**我们的记录**：
- `F.kl_div(input, target)` 点态 = `target · (log target − input)`；
- 因此 `F.kl_div(p.log(), q)` = `q·(log q − log p)` = **KL(q‖p)**；
- 论文标准 JS = `½[KL(p‖m)+KL(q‖m)]`，m=(p+q)/2；
- 官方实现方向与标准 JS 不同 → 名为 **reverse-JS-type divergence**
  （`½[KL(m‖p)+KL(m‖q)]`）。

验收：
- 验证者 Q4/Q5 与上述一致 → C3 的 reverse-JS 表述通过独立复核。
- 验证者证明确实算的是 KL(p‖q)（与我们相反）→ **以验证者的数学证明为准**，立即改写
  PCT 核查报告 §3.3 和骨架 C3。
- 验证者无法判定或两人都含糊 → 降级为"待更多核对"，论文不写确定性表述。

## Task B 验收（joint-KDE 数学性质）

**我们的记录**（第三轮终审后已撤回"独立假设"，改为）：
- `kernel_values` 形状 `(1, N, n_bins)`；
- `matmul(kv1^T, kv2)` = `(n_bins_p, n_bins_w)`，元素 `∝ Σ_s φ(b_i;w_s)·φ(b_j;p_s)`；
- 这是**配对样本 2D product-kernel KDE**，**不等于**边际乘积，**不蕴含独立**；
- 与标准 2D KDE 数学等价（同核同带宽下）。

验收：
- 验证者 Q5 判"不成立/部分成立"（即同意撤回独立假设）→ 撤回确认，可以写进治理记录。
- 验证者证明它确实是边际乘积（与我们相反）→ 我们需要重新核验官方 `marginal_pdf`/
  `joint_pdf` 源码，以仓库当前版本为准重判。
- 验证者指出归一化层面的差异 → 记录为"结构等价、归一化细节见其报告"。

## Task C 验收（第三编码员）

对比脚本（收回 `TaskC_coderD_你的名字.csv` 后运行）：

```bash
cd E:\论文1
.venv/Scripts/python.exe -X utf8 - <<'EOF'
import pandas as pd
from sklearn.metrics import cohen_kappa_score
import os
base = "08_报告与说明文档"
final = pd.read_csv(f"{base}/literature_coding_table_FINAL21.csv")
d = pd.read_csv(r"<你的文件路径>")   # 验证者填好的 coderD 表
m = final.merge(d[["paper_id","D1_provenance","D2_stage","D3_inference_req","D4_fidelity","D5_harm"]],
                on="paper_id", suffixes=("_final","_D"))
for dim in ["D1_provenance","D2_stage","D3_inference_req","D4_fidelity","D5_harm"]:
    a = m[dim+"_final"].tolist(); b = m[dim+"_D"].tolist()
    agree = sum(x==y for x,y in zip(a,b))/len(a)
    k = cohen_kappa_score(a,b)
    print(f"{dim:20s} agree={agree:.1%} kappa={k:+.3f}")
EOF
```

（若无 sklearn，用 `interrater_agreement_final.py` 里的 cohen_kappa 函数替换。）

仲裁规则：
- D4/D5 任一维度 κ<0.4 → 该维结论降级为"存在编码歧义"，正文加编码歧义讨论；
- D1–D3 三方两两 κ 显著低于 0.4 → taxonomy 该维度可靠性从"中等"下调为"低"，需修 schema。
- 逐条分歧：验证者与 coder_C 或 FINAL21 不一致的项，列出清单，按"更充分依据"仲裁。

## Task E 验收（训练实验）

验收只看两点：
1. **审查结论**：验证者是否发现代码与预注册协议不符。
   - 发现新的不符点 → 立即修复 or 作废对应结论，本轮修炼到此为止。
2. **重跑方向**：验证者 smoke 的 rel 方向（正/负/接近零）是否与协议预期一致。
   - 数值不必相等；方向一致即可算"复现"。
   - 跑不起来 → 记录环境问题，标记"不可复现"，不强行解释。
