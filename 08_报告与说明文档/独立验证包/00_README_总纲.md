## 一、要验证什么、为什么

经过五轮 reviewer 审查，研究包收敛到以下"可保留"资产。每一类都需要**独立于本作者**的复核，才能写进论文：

| 资产 | 验证方式 | 对应任务 |
|---|---|---|
| reverse-JS 实现差异（PCT 官方代码 vs 论文公式）| 独立数学推导 | **Task A** |
| joint-KDE 数学性质（撤回"独立假设"指控的确认）| 独立数学推导 | **Task B** |
| 21 篇语料 D1–D5 编码（κ 中等，需第三编码仲裁）| 盲法第三编码 | **Task C** |
| PRISMA 72→21 的排除判定（目前是 title 规则分类）| 盲法逐篇复核 | **Task D** |
| 修复后训练实验（leakage/单位修复后尚未正式重跑）| 协议 + 代码审查 + 独立重跑 | **Task E** |

## 二、优先级与时间估计

| 优先级 | 任务 | 验证者工作量 | 为什么排这个序 |
|---|---|---|---|
| P0 | Task A | ~2 小时 | C3 唯一幸存点；纯数学，最快，错了整段删掉 |
| P0 | Task B | ~2 小时 | 防止"撤回错了"；纯数学 |
| P1 | Task C | ~3–4 小时 | C2 可靠性；D1–D3 κ=0.385–0.436 需要第三编码仲裁 |
| P1 | Task D | ~4–6 小时 | 方法论完整性；51 篇排除记录 |
| P2 | Task E | 1–2 天 | 训练证据已降级为附录线索；只有前四项都过才值得做 |

**强烈建议按 A→B→C→D→E 顺序**。A/B 先做，它们如果出问题，E 就完全不必做。

## 三、盲法规则（最关键，务必执行）

验证者的判断不能被我们的结论锚定。执行三条：

1. **只发给验证者**：`01_任务书`、Task A–E 分册、以及分册里列出的原始材料（代码、指引、空白表）。
2. **绝对不发**：本 README、`08_验收与对比.md`、以及我们任何包含数值结论的文档
   （PCT官方代码核查报告、PriorSource替换实验、各轮终审响应、主线索引、论文骨架）。
3. **Task 之间不互通答案**：验证者做完 Task A 的报告再发 Task B 材料，不要一次全给
   （防止前面的任务锚定后面的判断）。C/D 可以一起给，E 最后给。

## 四、交接流程（你作为协调人的操作）

```
第 1 步：发 01_任务书 + Task A 材料
第 2 步：收回 Task A 报告 → 发 Task B 材料
第 3 步：收回 Task B 报告 → 发 Task C + Task D 材料（含空白表）
第 4 步：收回 Task C/D 报告 → 决定是否发 Task E
第 5 步：收回 Task E 报告 → 运行 08_验收与对比.md 里的对比脚本
```

## 五、验收判据（一句话版）

- **Task A**：验证者推导的 KL 方向与我们记录的一致 → 通过；不一致 → 以数学证明为准，改写结论。
- **Task B**：验证者确认"配对 2D product-kernel KDE ≠ 边际乘积、不蕴含独立" → 撤回成立；若他反驳 → 重新核验官方代码后再定。
- **Task C**：跑 `interrater_agreement_final.py` 的三方版本；任一维度 κ 显著下降或出现新的系统性分歧 → 该维度结论降级为"存在编码歧义"。
- **Task D**：验证者判定 vs 我们 title 规则的**分歧清单**逐条仲裁；一致率 <70% → PRISMA 数字不能写"精确"，改写"规则初筛 + 人工复核子集"。
- **Task E**：验证者重跑数值与协议判据对照；**只看方向与显著性是否一致**，不看数值相等（随机种子下允许数值差异）。
