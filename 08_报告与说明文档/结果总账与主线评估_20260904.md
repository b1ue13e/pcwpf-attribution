# 结果总账与主线评估（2026-09-04）

## 1. 先给结论

当前材料**不能直接支持一区投稿**；以现有证据完整度，也不宜把旧版 Ultra-LSNT 方法稿直接投二区。最稳妥的可投稿形态是：

> **一篇以“物理约束风电预测中的约束生命周期、实现忠实度与伤害报告”为核心的 scoping/empirical audit 论文；把训练模型结果降为背景或附录，把 PCT 的 reverse-JS 方向错误作为可复核案例。**

按当前证据，合理预期是“二区中下游或应用型期刊的大修后尝试”，前提是先关闭 PRISMA 覆盖、双人编码、协议版本和案例复现四个硬缺口；一区需要新增第二个独立、公开代码的方法族案例，或完成预注册的跨方法复现实验，不能靠继续堆模型表格实现。

## 2. 所有结果按证据等级归并

### C. 必须冻结、不得再作为正式结论

- 旧报告中的 Ultra-LSNT `R²≈1`、RMSE 58.7% 改善、20% 噪声下全面最优等数字：与当前可审计矩阵冲突，属于旧实验口径。
- “官方实现导致 RMSE 差 3–8×”：当前只能保留约 2–4× 的方向性线索，且需忠实 runner、原始数据、horizon、batch 和超参全部对齐后才能定量。
- “n=15 Wilcoxon p≤0.0001”“错误先验跨族显著有害”：已因 leakage/单位/协议问题撤回；现有 5-seed 结果至多是方向性线索（Wilcoxon 边界 p=0.0625）。
- “系统atic review 已覆盖领域总体”：当前 PRISMA 独立复核与 FINAL21 口径不闭合，不能使用领域级比例。

## 3. 能否汇聚成一条主线

可以，但主线必须从“提出一个更强的预测模型”改为：

> **物理约束并非一个单一模块，而是贯穿 provenance→application stage→inference requirement→implementation fidelity→harm reporting 的生命周期对象。若不区分这些层次，论文容易把训练期先验误写成部署期约束，并在实现、比较和伤害报告上产生不可见偏差。本文提出五维审计框架，用一个可公开核查的 PCT 代码/公式方向不一致案例展示其可操作性；风电模型与调度实验只用于说明这些审计维度为何影响鲁棒性、安全和部署决策。**

对应的结果叙事顺序应固定为：

1. 框架与预注册协议定义“审计对象”；
2. 语料编码给出 pilot-level field map，明确不外推总体比例；
3. PCT 案例给出一条数学上可复核的 specification–implementation mismatch；
4. Ultra-LSNT/guardrail/dispatch 结果作为 downstream stress test，说明 clean accuracy、noise robustness、safety 与 mapped operation 之间存在 trade-off；
5. 以限制和可复现清单收口，而不是再增加模型排名。

## 4. 分区可行性判断

| 目标 | 当前判断 | 决定性原因 |
|---|---|---|
| 一区（能源/AI 顶级应用） | **不支持** | 只有一个可执行代码案例；语料覆盖与双人编码未闭合；训练与调度协议仍有条件性证据；缺少跨方法独立验证和可推广机制 |
| 二区应用型 | **有条件支持，大修前不宜投** | 框架问题有价值，PCT 案例较硬，且有真实风电 stress-test；但需把论文从旧方法稿重构为 audit/scoping empirical paper，并关闭四项 P0 |
| 二区中下游/方法与可再生能源交叉期刊 | **最现实** | 允许“框架 + pilot audit + case study”的证据结构，但必须诚实标注 pilot、conditional、single-case |

## 5. 投稿前必须完成的四个硬门槛

1. **Protocol v2 与 PRISMA 闭合**：明确纳入标准，逐条保留 query、URL、日期、排除理由；统一 46/48/21 的 corpus 口径。
2. **真实双人 v4 编码**：同一全文材料、同一 schema v4，报告 inter-rater κ/α；不能把单人重编码稳定性当双人可靠性。
3. **PCT faithful rerun**：公开数据/代码、原论文 horizon=144、batch/epoch/lr、dynamic JS switch 全部对齐；否则只写 static audit，不写性能差异。
4. **清理活跃文档与旧稿**：删除 `R²≈1`、3–8×、n=15 显著性、NWP/未来值等撤回表述；将 Ultra-LSNT 旧稿与 audit 主线分离，避免审稿人发现自相矛盾。

## 6. 最终建议

当前最优策略不是继续扩充模型，而是把论文重构为一篇证据边界清晰的 audit paper：主文只保留 taxonomy、protocol、pilot field map 和 PCT 静态案例；所有 Ultra-LSNT、guardrail、dispatch、fairness 数字进入“stress-test/附录”并逐项标注协议限制。这样可形成一条自洽的二区投稿主线；在完成第二独立方法族案例和严格复现之前，不建议按一区标准承诺。
