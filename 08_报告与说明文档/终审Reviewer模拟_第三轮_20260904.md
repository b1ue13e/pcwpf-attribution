## 2. P0致命问题

### P0-1：PCT joint-KDE静态指控错误

官方代码形式：

```python
joint_kernel_values = K_power.transpose(1,2) @ K_wind
```

矩阵元素为：

\[
J_{ab}=\sum_i K_h(p_i-b_a)K_g(w_i-c_b),
\]

这是配对样本上的product-kernel joint KDE。只有`mean(K_power) outer mean(K_wind)`才对应边际乘积/独立性假设。当前报告把“每个样本核的外积后求和”误写成“两个边际密度的外积”。

**后果**：以下主张必须删除：

- PCT joint实现假设power⊥wind；
- outer-product破坏power-curve依赖；
- corrected true-joint修复了独立性错误。

此前loss仅约10%、gradient cosine≈0.99的结果反而与“两种写法近似同一product-kernel KDE”一致。

### P0-2：KL差异需要重新准确定性

若官方实现为：

```python
m = (p+q)/2
0.5*[kl_div(log p,m)+kl_div(log q,m)]
```

PyTorch计算的是`0.5[KL(m||p)+KL(m||q)]`。它不是标准JS，但仍是一个对称的reverse-direction divergence。应称`reverse-JS-type divergence / documentation–implementation mismatch`，不能笼统称“非规范KL破坏约束”。

静态审计需锁定官方commit、原函数上下文、PyTorch版本及数值epsilon，再由第二人独立复算。

### P0-3：无损骨架C3仍包含错误静态结论

当前骨架把“marginal outer product（independence假设）+ KL参数反了”作为全论文第三贡献。independence部分失效后，C3只剩一个reverse-JS差异。单个代码库的散度方向差异不足以单独支撑领域级audit贡献，必须重新评估C3分量。

### P0-4：PRISMA flow缺失51篇排除ledger

当前为89 identified→72 assessed→26 coded→21 included。最终纳入21意味着assessed阶段共有51篇被排除，但文档仅列编码后的5篇。剩余46篇没有逐篇ID、阶段与排除理由。17条web-search候选也未证明与OpenAlex 72条完成跨通道去重。

因此目前只能称`PRISMA-style scoping pilot`，不能称systematic field audit。

### P0-5：C2统计口径仍不一致

按`literature_coding_table_v4_arbitrated.csv`排除5篇后，21篇结果是：

- D5：18 none-reported、1 ablation-absent、2 harm-quantified；
- D4：20 no-code、1 code-mismatch。

`论文骨架_无损保留版.md`写19/21 none-reported，与实际表不一致。所有比例、摘要和图必须由最终included表自动生成。

### P0-6：D4“20/21 no-code”证据仍不足

`Code核查记录_D4.md`明确承认只做代表性GitHub/web检索，未逐篇穷举；Crossref没有data-availability metadata也不能推出没有代码。把20篇统一判`no-code`超过检索证据。更稳妥的类别应区分：

- `verified-no-public-code`；
- `not-found-after-protocol-search`；
- `unverified`；
- `official-code-found`。

### P0-7：修复后的训练证据尚不存在

PCT代码虽然改成未来1步target并接收epochs，但正式结果文件仍是旧作废版本；PI-TFN修复单位后只记录fixed-Cp约0.19的摘要，没有9-seed完整结果、CI与逐项loss诊断。因此当前不能恢复任何“constraint harm显著”或“跨族一致”结论。

评分：重要性7/10；创新性5/10；证据完整性3/10；Decision Reject。

### Reviewer 1：系统综述与编码

真人双编码是明显进步，诚实报告κ约0.39–0.44值得肯定。但这说明D1–D3只能中等可靠，需补充训练样例、决策树与敏感性分析。更关键的是最终21篇和编码26篇没有形成单一analysis-ready表，PRISMA缺51篇完整排除记录，代码可得性也未按统一协议逐篇核验。

评分：Transparency 4/5；Systematic rigor 2/5；Decision Major/Reject。

### Reviewer 2：软件与数学审计

KL方向差异可能是真实、可复现的软件审计发现。但joint-KDE被误判为独立性表明当前代码解读仍缺第二位熟悉KDE/PyTorch的审查者。建议先建立最小解析例子，证明官方矩阵乘法与product-kernel KDE的等价性，再只保留reverse-JS差异。未完成前不应公开指控原实现破坏物理结构。

评分：Audit idea 4/5；Current correctness 2/5；Decision Reject。

### Reviewer 3：风电与实证

PI-TFN单位修复及时，但没有原始架构、输入和物理参数，不能承担第二方法家族。PCT runner现在诚实降为one-step，但这已不再是PCT结构对齐。若训练实验继续放附录，应明确它们是本项目的stress-test prototypes，而不是外部方法复现。

评分：Domain relevance 4/5；External validity 2/5；Decision Major/Reject。

### Devil's Advocate

去除所有失效训练结果和independence指控后，论文剩下的是：一个五维编码框架、21篇小型语料中多数论文未公开代码/未报告负面影响，以及一个官方实现使用reverse-JS而非standard-JS的案例。审稿人可能认为这是有用的research note，但不足以支撑Applied Energy级“systematic empirical audit”。尤其“没有报告伤害”不等于“约束收益未经验证”，许多论文可能报告了正向ablation，只是没有主动展示负结果。

**CRITICAL**：C3 independence主张错误，必须撤回；C2需区分`harm not found`与`harm not tested`。
