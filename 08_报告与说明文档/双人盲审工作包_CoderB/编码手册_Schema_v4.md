# 物理约束生命周期编码手册（Schema v4）

> **审计核心定位**：
> 本文审计的是**物理约束在风电功率预测模型全生命周期中的角色、依赖与风险报告行为**。
> 涉及五个核心维度：
> **D1（参数来源）** $\rightarrow$ **D2（施加阶段）** $\rightarrow$ **D3（推理计算依赖）** $\rightarrow$ **D4（开源忠实度）** $\rightarrow$ **D5（消融与伤害报告）**。

---

## 核心铁律（编码前必读，防止最常见混淆！）

> 🌟 **【第一铁律：D1 与 D3 绝对独立】**
> - **D1 只问一句话**：“这个约束公式中的**参数/先验知识本身**从哪里来？”（是物理客观规律，还是从历史数据里拟合出来的统计先验？）
> - **D3 只问一句话**：“在**测试推理期**计算该模型时，**需要提供什么输入**？”（只需历史常态数据，还是必须额外提供未来的 NWP 气象预报？）
> - **典型示例**：解析尾流公式（如 Jensen Wake）：
>   - 公式本身是流体力学解析方程，不从训练数据里估计参数 $\rightarrow$ **D1 = `intrinsic`**；
>   - 推理时要计算尾流亏损，必须输入未来时刻的气象预报风速 $\rightarrow$ **D3 = `forecast-input`**。
>   - **绝对禁止**因为推理需要预报输入，就把 D1 误判为 forecast-derived！

---

## 维度详解与判定标准

### D0. 纳入资格核对（Inclusion Check）
在具体编码前，请先核查该论文是否属于风电预测范围：
- `include`：针对**风电功率（Wind Power）**的时间序列预测（Forecasting）或回归建模，且施加了某种显式物理约束/物理模块。
- `exclude`：纯风速预测（不预测功率）、或仅提到“物理”字眼但通篇没有任何具体物理公式/约束项。
  - *若判定为 `exclude`，请在 `exclusion_reason` 中简要说明原因，后续 D1–D5 字段**必须统一填入标准字符串 `N/A`**（严禁留空串或填入其他字符），以确保缺失语义在统计分析中的严格一致性。*

---

### D1. Provenance（参数来源 / 知识形态）
**核心问题：这个物理先验的参数或形态从哪里来？**

| 取值标签 | 严格定义 | 典型中立案例 |
| :--- | :--- | :--- |
| **`intrinsic`** | 参数是**不需从数据中估计的物理客观事实、铭牌常数或解析控制方程**。包括：Betz 极限（16/27）、额定功率上界、切入/切出风速、解析气动方程（$P=\frac{1}{2}\rho C_p A v^3$）、解析尾流模型、流体力学 Navier-Stokes 控制方程。 | 基于流体力学与转子几何常数的理论功率控制方程；标准流体动力学解析方程。 |
| **`historical-static`** | 先验的**参数从历史观测/运行数据中拟合或统计提取**，在模型训练开始前固定冻结，训练期不再更新。包括：从历史数据估计的经验功率边界、经验分位数统计包络、历史经验散点拟合曲线。 | 预先基于历史观测集统计拟合的分位数上限先验或离线经验分布包络。 |
| **`learned-online`** | 物理先验的**参数在神经网络反向传播过程中随模型一起动态训练更新**。如：可训练的风能利用系数 $C_p(\lambda, \beta)$ 拟合网络、自适应物理权重。 | 随主干网络反向传播联合微调的可微物理参数分支。 |
| **`unreported`** | 论文提到了物理先验，但完全未交代其参数是固定的、解析的还是拟合的。 | 无法从原文推断参数来源。 |

---

### D2. Application Stage（约束施加阶段）
**核心问题：约束在模型生命周期的哪一个技术环节生效？**

判定原则（四段分水岭）：
1. 它是作为损失函数的 penalty 正则项吗？$\rightarrow$ `training-loss`
2. 它是前向网络不可分割的一个计算层或分支吗？$\rightarrow$ `inference-architecture`
3. 它是用来造数据的吗？$\rightarrow$ `data-generation`
4. 它是模型输出之后的后处理调整吗？$\rightarrow$ `post-hoc-correction`

| 取值标签 | 严格定义 | 典型中立案例 |
| :--- | :--- | :--- |
| **`training-loss`** | 约束作为**目标函数（Loss Function）的惩罚项/正则化项**。其影响是通过梯度反向传播调整模型权重，在推理前向计算中不显式计算物理方程。 | $\mathcal{L} = \mathcal{L}_{\text{task}} + \lambda \mathcal{L}_{\text{phys}}$（如控制方程残差惩罚、概率散度正则项）。 |
| **`inference-architecture`** | 约束被**深度硬编码进推理网络架构本身**（如物理分支、带物理拓扑的图神经网络邻接矩阵、机理公式特征变换层）。去掉这一层，前向推理就无法执行。 | 解析气动物理变换流与神经网络特征融合拼接；基于物理拓扑构图的图神经网络。 |
| **`data-generation`** | 约束用于**离线合成、扩增训练样本或构造伪标签**（如物理引导的 Diffusion 或 GAN），预测模型本身仅在扩增数据上训练。 | 离线生成模型采样中基于物理边界包络的重投影与无效样本过滤。 |
| **`post-hoc-correction`** | 约束在**模型推理输出之后**生效，对预测值进行事后裁剪、映射或校准。 | 预测输出之后执行的物理边界截断 $\min(\max(\hat{y}, 0), P_{\text{rated}})$；事后保形区间物理裁剪。 |
| **`unreported`** | 原文未清晰交代实现位置。 | - |

### D3. Inference Requirement（推理期计算依赖）
**核心问题：在测试期/部署期进行单步或多步推理时，计算这个先验/模型需要什么额外输入？**

| 取值标签 | 严格定义 | 典型中立案例 |
| :--- | :--- | :--- |
| **`none`** | 推理只需**常规历史数据**（历史 SCADA、历史气象、历史功率），不需要任何未来信息或非标准传感器。 | 标准自回归历史功率序列或历史气象滑窗输入。 |
| **`forecast-input`** | 推理时**必须依赖未来时步的数值天气预报（NWP）产品**（如未来 24 小时的 WRF 预报风速、ECMWF 气象场）。 | 前向推理需要未来待预测时段的数值天气预报（NWP）气象场驱动。 |
| **`contemporaneous-state`** | 推理时需要**当前时刻可观测的实时高阶机组物理状态**（如实时变桨角 Pitch Angle、实时叶尖速比 TSR、实时限电标记）。 | 推理需接入机组当前毫秒级变桨角、转速或控制模式标记。 |
| **`latent-state`** | 推理时需要**当前时刻无法直接测量的隐状态/反事实变量**（如由于电网限电 curtailment 而被遮蔽的“本可发电量” Theoretical Power）。 | 依赖电网未限电反事实潜在功率等不可测状态。 |
| **`unreported`** | 论文没有交代推理期需要哪些输入变量。 | - |

### D4. Implementation Fidelity（代码可用性与保真度）
**核心问题：作者是否开源了官方代码？开源代码与论文数学公式是否一致？**

| 取值标签 | 判定标准 |
| :--- | :--- |
| **`code-aligned`** | 论文提供了官方可访问的公开代码仓库链接，且代码中的物理约束实现与正文公式在数学定义上严格一致。 |
| **`code-mismatch`** | 提供了官方代码，但核心实现与论文公式存在**数学意义、参数传递或计算逻辑上的实质性冲突**（如正文定义对称测度但代码调用非对称算子，或传参顺序颠倒导致实际优化目标异于声明定义）。 |
| **`not-found`** | 全文检索（正文、脚注、Data Availability、致谢）未找到公开代码链接，或提供的链接已失效（404）。 |
| **`unverified`** | 提供了代码仓库，但尚未进行代码级语法和算子核验。 |

### D5. Harm & Ablation Reporting（消融实验与伤害报告）
**核心问题：论文是否严谨评估了物理约束的独立收益？是否报告了约束可能的负面效应？**

#### 子字段 1：`ablation_type`（消融类型）
- **`constraint-on-off`（严格物理消融）**：作者做了“有约束 vs 无约束”的严格对照（如令 $\lambda=0$ 或关闭物理损失项，其余网络结构、超参数完全不变）。
- **`module-ablation`（宽泛模块消融）**：作者把包含物理约束的整个复合子模块（如 GCN 分支、Attention 模块）一并拔掉，无法剥离到底是模块参数量增加带来的增益还是物理先验本身的贡献。
- **`both`**：既做了模块消融，又做了纯约束的开关消融。
- **`none`**：完全没有做任何对照消融实验。

#### 子字段 2：`negative_effect_reported`（是否报告负面效应）
- **`no`**：通篇宣称加入物理约束后所有指标全面提升（100% 论文常见现象）。
- **`yes`**：明确报告了物理约束在某些指标、某些数据集或某些超参数下导致性能下降（如报告了在 Clean 场景下 RMSE 变大、或推理延迟显著增加）。
