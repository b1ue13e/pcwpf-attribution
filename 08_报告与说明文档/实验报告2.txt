### 1.3 模型实现细节

#### 1.3.1 Ultra-LSNT核心架构
- **框架**: 基于PyTorch原生实现，无第三方依赖
- **MoE实现**: 自定义稀疏专家混合层，支持Top-K路由（K=2）
- **跳跃门控**: ConsistentSkipGate模块，结合重要性评估与变化检测
- **双模传播**: DualModePropagation模块，支持快速与慢速路径
- **正则化**:
  - **Load-balancing loss**: 路由器负载均衡损失，默认系数 λ=0.01
  - **Z-loss**: 路由稳定性损失，默认系数 λ=0.01
  - **消融研究最佳值**: 通过消融研究确定负载均衡损失的最佳系数为 **λ=0.05**（见4.2节）
  - **主表结果**: 本文所有主表（Table 3, 4, 5等）中Ultra-LSNT的性能均基于 **λ=0.01** 训练得到，以确保与基线模型（均使用其默认/标准超参数）的公平对比。
  - **性能提升潜力**: 若采用消融研究确定的最优系数 λ=0.05，Ultra-LSNT在风电数据集上的R²预计可从0.8728提升至0.8832（相对提升约+1.2%）。
  - **论文处理策略**: 为保持超参数一致性并避免引入额外的调优自由度，主结果保留λ=0.01。消融研究结果（λ=0.05最优）证明了Ultra-LSNT对超参数的敏感性，并为其实际部署提供了优化指导。

#### 1.3.2 训练配置
- **优化器**: AdamW (β₁=0.9, β₂=0.999, weight_decay=0.01)
- **学习率调度**: Cosine annealing with warmup (初始lr=1e-3)
- **批大小**: 128 (训练), 256 (推理基准测试)
- **训练轮数**: 10-50 epoch，根据模型复杂度调整
- **混合精度**: AMP (Automatic Mixed Precision) 用于加速训练

#### 1.3.3 推理优化
- **编译优化**: `torch.compile` with `max-autotune`模式
- **内存管理**: 显存缓存与重用策略
- **快速推理模式**: 特定配置下的优化推理路径
- **批处理**: 动态批处理支持

### 1.4 实验复现性保障
1. **随机种子固定**: 设置全局随机种子 (seed=42)
2. **确定性算法**: 启用CUDA确定性模式确保相同硬件下结果一致
3. **环境隔离**: 使用Python虚拟环境 (.venv/) 管理依赖
4. **日志记录**: 所有实验均有完整日志 (logs/, logs_complete/目录)
5. **数据版本控制**: 原始数据与预处理数据分离管理

### 1.5 边缘设备适配性
- **模型量化支持**: 支持FP16/INT8量化推理
- **内存优化**: 动态内存分配与释放
- **低精度运算**: 支持混合精度推理
- **硬件特定优化**: 可针对Jetson Nano等边缘设备优化

### 6.4 风速突变事件检测器规则

在专家切换分析中，使用 `analyze_expert_switching_standard.py` 脚本的风速突变检测器（`find_wind_ramp_events` 函数）识别关键事件。检测器具体规则如下：

#### 6.4.1 检测器参数
| 参数 | 默认值 | 说明 |
|------|--------|------|
| **Δ阶数** | 一阶差分 | 使用窗口两端点的原始差值：Δ = wind_speed_seq[i + window] - wind_speed_seq[i] |
| **窗口长度** | 10（默认）/ 12（实际使用） | 检测时间窗口大小（15分钟间隔） |
| **阈值 δ** | 5.0 m/s（默认） | 突变事件的绝对值阈值；若未检测到事件则降至3.0 m/s |
| **归一化** | 否 | 使用原始风速值（m/s），未进行归一化 |

#### 6.4.2 检测规则
1. **滑动窗口**：在风速序列上以步长1滑动，对每个位置 i 计算窗口 [i, i+window] 内的风速变化 Δ。
2. **事件判定**：若 |Δ| ≥ δ，则标记为一个突变事件。
3. **事件类型**：Δ > 0 为上升事件（increase），Δ < 0 为下降事件（decrease）。
4. **事件排序**：按 |Δ| 降序排列，选取最显著的事件进行分析。

#### 6.4.3 实际使用参数
在实际分析中（`analyze_expert_switching_standard.py` 第244-250行）：
- **首次检测**：window=12, δ=5.0 m/s
- **若未检测到事件**：降低阈值至 δ=3.0 m/s（保持 window=12）

#### 6.4.4 检测器数学表示
\[
\Delta = x_{t+W} - x_t
\]
\[
\text{event detected if } |\Delta| \geq \delta
\]
其中：
- \(x_t\)：时间点 t 的风速值（m/s）
- \(W\)：窗口长度（默认10-12个时间步，每个时间步15分钟）
- \(\delta\)：检测阈值（默认5.0 m/s）

### 6.5 关键发现总结

1. **自发分工**：模型在没有显式监督的情况下自发学习物理特征分工
2. **时间模式学习**：专家还学习时间依赖模式，增强了对周期性变化的建模能力
3. **事件响应**：专家激活模式对物理事件有可解释的响应
4. **物理意义明确**：专家分工与风电功率预测的物理机理高度一致
5. **创新价值**：首次在MoE架构中观察到这种多维度（特征+时间+事件）的自发学习

## 十一、核心结论与贡献

### 11.1 技术贡献

1. **架构创新**：提出Ultra-LSNT稀疏MoE架构，首次将稀疏专家混合应用于风电时序预测
2. **效率突破**：开发Ultra-LSNT-Lite优化版本，在推理延迟、能耗效率和模型大小方面全面超越TimeMixer
3. **鲁棒性验证**：在20%输入噪声下性能仅下降2%，显著优于传统方法
4. **可解释性发现**：首次观察到MoE专家自发学习物理特征分工，提供新的可解释性视角
5. **应用价值证明**：在风电调度优化中可节省6.5-14.7%成本，具有显著经济效益

### 11.2 性能优势总结

1. **准确性**：Ultra-LSNT在风电预测上达到R²=0.8728，在深度学习模型中排名第一
2. **效率**：Ultra-LSNT-Lite优化版推理延迟6.53ms，能耗9.80mJ，模型大小1.33MB
3. **鲁棒性**：20%噪声下性能下降仅2%，高噪声环境下显著优于LightGBM
4. **泛化性**：在4个不同领域均表现稳定，展现良好跨领域能力
5. **可解释性**：专家自发学习物理特征分工，提供直观物理解释

本项目的所有实验结果充分支持论文主题"Ultra-LSNT: An Efficient Sparse Mixture-of-Experts Network for Edge-Native Wind Power Forecasting with Superior Robustness and Interpretability"：

1. **Efficient**：通过Ultra-LSNT-Lite优化版本证明了高效率（6.53ms推理延迟）
2. **Edge-Native**：小模型尺寸（1.33MB）和低能耗（9.80mJ）适合边缘设备部署
