# Ultra-LSNT 最终实验结果综合报告（收口版，更新到 2026-03-02）

## 0. 本版口径（重要）

本版用于投稿前“最小修复包”收口，口径如下：

- dispatch 证据按 **conditional evidence** 报告：
  排名仅在 fixed affine mapping + feasibility clipping 的 mapped protocol 下可比。
- TSFM（Chronos/Moirai）**不纳入本次投稿的任何定量证据**（主文与补充均不作为定量比较证据），仅保留非定量背景定位。
- expanded metaheuristic（PSO-BPNN/GWO-SVR/HPO-CNN-LSTM）由于 constrained budget 设定，
  **降到 supplementary diagnostics**，不参与主文主结论排名。
- fairness 本轮补强为：
  DLinear / iTransformer / TimeMixer，2 seed（42/2025），训练期采用非高斯 Drift augmentation。
- guardrail 机制本轮补 1 个最小对照：
  `Ultra-LSNT(no guardrail) / Ultra-LSNT+clip-only(posthoc) / FG-MoE(full-trained)`。

## 2. Dispatch 价值（条件性证据）

数据源：

- `results/supplementary_evidence/main4_matrix4_dispatch_value.csv`
- `applied_energy_final_results/supplementary_evidence/dispatch_raw_vs_mapped_summary.csv`

### 2.1 可比性闸门

raw-scale 下 120 天所有模型均为 fallback-only（optimized ratio = 0），
因此不能直接据此做经济性排名。

mapped protocol 下恢复可比：

- iTransformer 在 L1/L2 映射后指标中最优（成本、弃风、fallback 或 gain）
- Ultra-LSNT 不是 mapped 排名第一
- 但 Ultra-LSNT 相对 DLinear 仍有明确改善：
  - L1 成本改善：33.96%
  - L2 弃风改善：12.01%
  - fallback：75 天 -> 29 天

结论：dispatch claim 仅作为固定映射 operating point 下的条件性证据，不作“全面更优”表述。

### 2.2 Mapping sensitivity（wmax260 / wmax280 / wmax300）

新增归档聚合脚本：`build_dispatch_mapping_sensitivity_from_archives.py`  
并新增 `wmax300` 一次轻量 rerun（其余点复用既有归档）。

输出：

- `results/supplementary_evidence/dispatch_mapping_sensitivity_wmax260_280_300.csv`
- `results/supplementary_evidence/dispatch_mapping_sensitivity_wmax260_280_300.meta.json`

关键观察（L2 RTS-24）：

- 在 `wmax260` 与 `wmax280` 区间下，iTransformer/TimeMixer 在 mapped curtailment 指标上仍略优于 Ultra-LSNT；
- 在新增 `wmax300` 点，三者（iTransformer/TimeMixer/Ultra-LSNT）相对 DLinear 的 curtailment gain 仍为正（约 +0.94%）；
- Ultra-LSNT 相对 DLinear 的 curtailment 改善在三点都保持为正（约 +12.01%、+3.94%、+0.94%）；
- 方向稳定，但本质仍是 mapped-protocol conditional evidence。

### 2.3 Mapping day-level consistency（wmax260 / wmax280 / wmax300）

新增归档日级一致性脚本：`build_dispatch_mapping_daylevel_consistency.py`（无新重跑）。  
输出：

- `results/supplementary_evidence/dispatch_mapping_daylevel_consistency_wmax260_280_300.csv`
- `results/supplementary_evidence/dispatch_mapping_daylevel_consistency_wmax260_280_300.meta.json`

双层证据结构（Supplementary S3 + S3b）：

- 聚合层（S3）：用于判断跨 mapping corridor 的方向性是否保持；
- 日级层（S3b）：用 `day-win ratio` 与分位差（median/p25/p75）披露稳定性频率；
- 结论层：聚合优势与日级稳定性可不一致，因此 dispatch 仍按 mapped-protocol conditional evidence 报告，而非“天然系统可用性”结论。

## 3. Fairness 补强（三基线，2-seed，Drift）

新增脚本：`run_minimal_matched_robustness_controls_v2.py`

执行命令：

```bash
python run_minimal_matched_robustness_controls_v2.py --models dlinear,itransformer,timemixer --seeds 42,2025 --finetune-epochs 1 --train-perturb drift --train-severity-max 0.4 --test-perturb drift --test-grid 0.0,0.4 --batch-size 128 --lr 1e-4
```

输出：

- `results/supplementary_evidence/fairness_minimal_aug_controls_drift_2seed.csv`
- `results/supplementary_evidence/fairness_minimal_aug_controls_drift_2seed.summary.csv`
- `results/supplementary_evidence/fairness_minimal_aug_controls_drift_2seed.meta.json`

### 3.1 关键结果（drift, σeff=0.60）

- DLinear：R² 0.8730 -> 0.8999（+0.0269）
- iTransformer：R² 0.8267 -> 0.8773（+0.0505）
- TimeMixer：R² 0.8263 -> 0.8622（+0.0359）

说明：这是增强版 minimal fairness control（2-seed + 1 non-Gaussian），但仍非 full-protocol/full-fault 闭环。

### 3.2 Guardrail 机制最小对照（clip-only）

新增脚本：`run_clip_only_guardrail_control.py`

输出：

- `results/supplementary_evidence/fgmoe_clip_only_control_windcn.csv`
- `results/supplementary_evidence/fgmoe_clip_only_control_windcn.meta.json`

关键结论（\(\sigma_{\mathrm{eff}}=0.60\)）：

- `Ultra-LSNT (no guardrail)`：R²=0.8502，over-rated=0.0656%
- `Ultra-LSNT + clip-only (posthoc)`：R²=0.3773，over-rated=0.0000%
- `FG-MoE (full-trained)`：R²=0.8526，over-rated=0.0023%

解释：clip-only 可以把违规压到 0，但代价是显著精度下降；FG-MoE 在“精度+违规”联合维度更均衡。

## 4. 本轮修订后主张边界

- Ultra-LSNT 的稳定定位是：
  bounded-compute robustness operating point + guardrail safety + 对 DLinear 的稳定改进。
- Ultra-LSNT 不主张 clean 全面最优，也不主张 mapped dispatch 全面最优。
- CEEMDAN-WOA-GRU 与 iTransformer 在部分指标更强，这一点在主文保留并明确。
- Threats-to-Validity 防守矩阵已集中放入 supplementary（`tab:threats_validity_matrix`），用于对 fairness / mapping / physics / hardware / AC 闭环边界做逐项披露。
