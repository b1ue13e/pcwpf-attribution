# 🚫 强行锁定反偷懒指令模板 (Negative Prompting Rules)

当你在向智能体派发涉及核心代码生成、算法实现、模块重构的任务时，可以直接在 Prompt 开头或结尾复制注入以下模块，强行锁死模型的“偷懒本能”：

---

### 📋 注入模板 A：极简强约束版（适用于代码补全与单函数生成）

```markdown
【硬性交付约束 / ANTI-LAZINESS GUARDRAILS】
1. 严禁使用任何 TODO, FIXME, pass, ..., 或注释占位符（例如 /* ... existing code ... */ 或 # 其余逻辑类似）；
2. 必须给出完整、可立即执行的生产级代码，所有 import、类型注解与异常处理必须全部写全；
3. 严禁省略重复逻辑或边缘分支，所有边界条件必须显式逐行写出。
```

---

### 📋 注入模板 B：科研与顶会工程级版（适用于算法推导与严谨实验代码）

```markdown
【顶级科研实验实现铁律】
1. 【零占位符铁律】: 严禁在任何函数或类中留下未实现标记（如 `pass`、`raise NotImplementedError` 或占位注释）。如果不确定如何实现，请显式停止并向人类提问，绝不可擅自用伪代码或常数糊弄。
2. 【全分支展开】: 所有数据校验、空值检查、矩阵维度对齐、除零保护、NaN/Inf 检查必须全量逐行编码，禁止使用“此处省略校验”等字眼。
3. 【自包含与可复现】: 生成的代码必须具备完整的依赖导入（imports）、全局配置提取、固定随机种子设定，以及可由 `pytest` 或 CLI 直接调用的验证入库逻辑。
4. 【无外部污染】: 严禁硬编码未经验证的魔法常数，所有数学/物理指标的门限和超参数必须显式声明在配置文件或参数字典中。
```

---

### 📋 注入模板 C：长代码替换专用（用于 `replace_file_content` / 编辑文件）

```markdown
【代码编辑反缩写约束】
1. 在生成替换代码块时，禁止用 `// ... rest of the method unchanged ...` 代替未修改的代码段；
2. 如果修改范围涉及整个函数，请输出从 `def/class` 开始到该结构结束的完整代码块，确保替换后语法解析树 100% 完整无破损。
```
