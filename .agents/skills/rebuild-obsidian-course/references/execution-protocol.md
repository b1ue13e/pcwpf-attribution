## 任务层级

### `local_task`

适用于单张知识卡、单个公式、链接、Frontmatter、单份作业或阶段内小修。只检查当前文件、直接权威关系和受影响入口。发现历史欠债就记录，不补建整门课程，不要求 A/B 验收。

### `full_course`

适用于用户明确要求新建、完整重构、系统补全或治理一门课程。执行来源、前置、路径、阶段、知识卡、作业、验证和课程级审计，并维护唯一执行清单。

### `formal_release`

适用于正式发布或宣布整门课程完成。除 `full_course` 全部要求外，必须达到总分 `≥85`、每维 `≥16`、无阻断问题，并通过 A 或 B 级独立验收。

## 唯一执行清单

完整课程使用：

`03-Projects/<路径>/质量审计/课程重构执行清单.md`

每个批次至少记录：

- `batch_id`
- 课程与阶段
- 文件范围
- 允许操作
- 执行者
- `base_commit`
- 当前状态
- 已修改文件
- 已运行检查及结果
- `checkpoint_commit`
- 阻塞项
- 下一步动作
- 开始与更新时间

状态不得跳级：

```text
batch_status: planned → claimed → in_progress → validated → committed → merged
card_status: planned → in_progress → content_checked → relation_checked → validated
异常状态: blocked | failed | needs_review
```

未实际验证不得标记 `validated`；未形成可恢复提交不得标记 `committed`。不要使用聊天摘要、临时计划或 Agent 记忆替代执行清单。

## 阶段批次

一门课程是治理单位，一个阶段是默认执行批次。一个批次原则上只包含：

- 一个阶段 MOC；
- 该 MOC 直接收录的知识卡；
- 与这些卡直接关联的作业；
- 为完成本阶段必须修改的课程入口、来源索引和治理记录。

跨阶段大规模移动、重命名或合并先拆为可独立验证的批次。一个批次未验证时，不开始依赖它的下一批次。

批次事务：

1. 读取执行清单、入口、阶段 MOC、目标文件和 Git 状态。
2. 确认范围与 `base_commit`。
3. 建立恢复点。
4. 对移动、合并、重命名和清退 dry-run。
5. 完成当前批次修改。
6. 运行 Frontmatter、路径、链接、表格、占位符和目标代码检查。
7. 检查 `git diff --check`、文件清单和关键 diff。
8. 标记 `validated`。
9. 按用户授权与仓库规则创建检查点提交。
10. 记录 `checkpoint_commit` 后再标记 `committed`。

## 逐卡事务

知识卡正文必须逐卡读取、逐卡判断、逐卡编写、逐卡检查。每张卡按以下顺序完成：

1. 读取当前卡、阶段 MOC、相邻卡、重复候选和可靠来源。
2. 判断保留、补写、合并、迁移、新建或清退。
3. 确认文件名、目录、课程口径、`stage_moc` 与直接 `upstream`。
4. 独立编写当前概念的完整正文。
5. 核验定义、公式、条件、推导、例子、误区、代码和来源。
6. 检查与相邻卡的重复、缺口和顺序。
7. 检查 Frontmatter、Wikilink、Dataview 派生关系与作业依赖。
8. 运行当前卡的最小质量检查并记录结果。
9. 标记 `validated` 后才开始下一张。

允许脚本做文件清单、精确搜索、重复候选扫描、Frontmatter/链接/表格检查、机械移动和引用修复、运行测试及生成不含知识正文的清单骨架。

禁止脚本或批量模型调用生成、重写、扩写、翻译多张知识卡正文；禁止只替换标题和变量复制同一内容；禁止批量创建空壳或先填 Frontmatter 后假定正文会补齐。

## 治理边界

治理清单统一写入 `03-Projects/<路径>/质量审计/课程严苛审计.md`，不要每次新建报告。每项包括路径、问题、影响、严重度、动作、canonical 文件、目标位置和待修复链接。

严重度：

- `阻断当前任务`：歧义链接、空壳依赖、损坏入口、目录冲突或双作业源使当前任务无法正确完成。
- `影响正式发布`：当前局部任务可完成，但整门课程不能发布。
- `历史欠债`：不影响当前任务或当前发布范围。

默认只记录后两类。只有阻断当前任务或用户明确授权课程治理时才执行历史迁移、合并和清退。

个人批注、主动回忆、错题和实验记录不能仅因文笔差而删除。合并必须保留独有且正确的内容；清退必须先恢复备份、修复引用并记录理由。

低质量文件不等于无价值文件：若仍有少量有效内容，先提取并合并到 canonical 文件，再决定是否清退；删除前必须确认有效信息、独有来源和全部引用已处理。

## 恢复与并发

恢复任务时先读执行清单和 Git 状态：

- `merged/committed`：只做一致性复核。
- `validated` 未提交：先核对文件和 diff。
- `in_progress`：从记录的文件范围和最后检查继续。
- `blocked`：先确认阻塞是否解除。
- 文件状态与清单不一致：停止写入并标记 `needs_review`。

同一时间默认一门课程只有一个主写入者。同课程必须并行时使用独立分支或 worktree、互斥文件范围和共享文件单写者；课程路径、来源索引、作业总索引、执行清单和严苛审计文件不得多写者并发修改。

## 分层完成标准

### 普通任务

- 用户要求的当前产物已完成。
- 当前文件目录、字段、命名、来源和版权正确。
- 当前文件及直接权威关系已同步。
- 已运行匹配本次改动的最小检查。
- 历史欠债已记录但未擅自扩张范围。
- 本次未引入死链、重复事实源、虚构来源、伪造结果、未说明占位符或损坏表格。

### 完整课程正式发布

在普通任务标准之上还要求：

- 全部必需前置可学习、可理解、可验收，并纳入前置 MOC。
- 全部知识卡归入阶段目录，路径、阶段 MOC、`stage_moc/upstream` 和派生视图完整。
- 作业按规模进入 `03-Projects`，形态正确，`requires` 只引用已教授知识。
- 历史改编作业已审查，保留项详细、可执行、可验收。
- 核心知识覆盖完整且保留课程语境。
- 五项教学质量均达标。
- 来源最少充分，多源融合自评达标。
- 不存在可以无损删除的重复结构和低价值资产。
- 全课程审计、运行验证和 A/B 级验收通过。
