# Gemini 3.7 Flash 长篇小说创生与智能索引 Skill

本 Skill 规定了使用 **Gemini 3.7 Flash** 进行高质量长篇小说创作、世界观构建、伏笔台账管理以及“防吃书”一致性审查的标准作业流程（SOP）。

---

## 1. 模型核心能力与动态模式调度 (Tuning & Modes)

Gemini 3.7 Flash 具备 **1M+ 超长上下文**、**混合推理思考能力（Thinking Mode）** 与 **极高吞吐流式输出**。必须根据创作任务阶段动态切换模式：

| 任务阶段 | 推荐模式配置 | 核心目标 | 关注重点 |
| :--- | :--- | :--- | :--- |
| **大纲推演 / 破局构思** | `Thinking Mode: ON` (高思考预算) | 推演多方势力动机、伏笔闭环与反转逻辑 | 确保因果闭环、拒绝机械降神、设计多解推演 |
| **单章细纲与场景拆解** | `Thinking Mode: ON` (中思考预算) | 场景四要素拆解与情感/悬念锚点设计 | 明确本章信息差、核心冲突与 3 阶段推进节奏 |
| **正文流式创生 (Drafting)**| `Thinking Mode: OFF / LOW` (极速流式) | 沉浸式场景描写、动作流、台词与感官细节 | 保证高吞吐、行文节奏紧凑、文学质感统一 |
| **防吃书审查 (Consistency)**| `Thinking Mode: ON` (强逻辑审计) | 校验正文是否违背设定集、神债台账与伤病状态 | 发现战力崩溃、人设 OOC、记忆错乱与时间线漏洞 |
| **新设定提取 (Lore Extract)**| `Thinking Mode: OFF` (结构化 JSON) | 自动从正文中提取新增人物/地点/法术/道具并建档 | 实体去重、属性归纳、生成标准 Markdown 卡片 |

## 2. 设定圣经与 Context Caching 机制

长篇创作的根基是“设定圣经（World Bible）”。通过 Gemini 的 **Context Caching** 机制，将长期稳定的高频上下文锁定在缓存中：

```
┌─────────────────────────────────────────────────────────────┐
│              Gemini Context Caching 缓存区 (常驻)            │
│  - 00_世界观设定/ (力量法则、神债体系、地理与势力)            │
│  - 00_人物档案/ (主角状态表、核心配角、反派动机)              │
│  - 01_大纲总纲/ (400章重构总纲、核心终局命题)                 │
│  - 01_台账/ (神债、伏笔、记忆与旧章映射连续性台账)            │
└──────────────────────────────┬──────────────────────────────┘
                               │ + 当前任务动态输入
┌──────────────────────────────▼──────────────────────────────┐
│              单轮执行动态上下文 (Dynamic Context)           │
│  - 当前卷大纲 + 当前章细纲                                   │
│  - 前 1~2 章正文结尾 (约 1500~2000 字用于承接上下文)         │
│  - 场景触发的人物状态 (最新伤势、所持道具、欠债阶段)         │
└─────────────────────────────────────────────────────────────┘
```

## 3. 商业节奏与长篇小说硬规则 (Rhythm Rules)

任何章节生成必须严格服从以下节奏铁律：

1. **篇幅标准**：单章建议 **2000—2400 字**。
2. **双项推进**：每章必须至少推进“**事件、关系、谜团**”中的两项，并产生至少一种实质变化（获得、失去、发现、失败、身份变化、关系变化、力量变化、地图变化、敌人升级）。
3. **禁止无效停留**：严禁连续两章只由聊天、解释设定、纯赶路或无动作的情绪停留构成。
4. **3-5-10 节奏律**：
   * **每 3 章**：必须完成一个已经建立的问题或期待（小兑现）；兑现后立刻抛出更大问题。
   * **每 5 章**：至少发生一次**不可逆变化**（人物决裂、关键道具损毁、地标覆灭、不可逆负债）。
   * **每 10 章**：至少推翻一次人物或读者的**局部认知**（反转/揭露新真相），并保留一次直接、视觉化的实力兑现。
5. **设定引入克制**：前 10 章每章最多引入 1 个新概念/专名；**概念必须先在事件中发挥作用，再允许给出解释**。
6. **闪回约束**：每 5 章最多 1 次完整闪回；闪回必须改变当下人物选择或推翻既有理解，严禁纯粹交代技能背景。

## 4. 文风与文学表现力规范 (Anti-Slop & Cinematic Style)

严禁一切 AI 生成的典型套路与低质网文通病：

### ❌ 严厉禁止的 AI 写作顽疾 (Forbidden Slops)
- ❌ **禁止“翻译腔与空洞抒情”**：如“他的心中涌起一股难以言喻的复杂情感”、“空气中仿佛弥漫着某种说不清道不明的压抑”。
- ❌ **禁止“总结式说教与升华”**：每段结尾擅自总结人生哲理（如“这就是成长的代价吧”、“或许，真正的救赎在于……”）。
- ❌ **禁止“旁白越俎代庖”**：直接用旁白宣告角色聪明或威严，而不是通过角色行动、微表情和受害者反应来展现。
- ❌ **禁止“战力描写空洞化”**：滥用“毁天灭地”、“不可名状”、“强横无比”等虚词，缺乏距离、重量、音效、材质破坏与生理痛感等物理锚点。

### ✅ 必须贯彻的影视级青年幻想文风 (Required Style)
1. **镜头感与空间锚定**：开场先建立光源、气味、天气与环境遮蔽物（如“冷雨砸在青石板上的声响”、“铁锈与火药的焦苦味”）。
2. **动作流代替心理独白**：用具体的身体微动作展现心理（攥紧剑柄的指节发白、咽下带血的唾沫、视线避开对方眼睛）。
3. **台词克制与潜台词（Subtext）**：人不说全真话，话中有话；长篇对话中夹杂动作交锋，禁止两人木桩式一问一答。
4. **疼痛与代价的生理真实感**：描写伤口撕裂的灼烧感、失血带来的视线重影、骨骼承受重击时的酸涩钝响。

## 5. 标准创作管线与执行四步法 (4-Step Pipeline)

```mermaid
flowchart LR
    A[Step 1: 细纲与锚点拆解] --> B[Step 2: 流式正文撰写]
    B --> C[Step 3: 防吃书一致性审计]
    C --> D[Step 4: 台账同步与新设定提取]
```

### Step 1: 细纲与锚点拆解 (Scene Blueprint)
输入当前章目标，拆解为三个微场景（800字左右一个场景）：
* **场景一（起/切入）**：当前紧迫问题、环境压迫、人物切入动作。
* **场景二（承/冲突加剧）**：遭遇阻碍、信息差暴露、代价借力或力量交锋。
* **场景三（转与合/悬念钩子）**：局部兑现、不可逆后果出现、章末悬念留白（Hook）。

### Step 2: 正文流式生成 (Drafting)
调用 Gemini 3.7 Flash 进行高密度正文生成，保持动作紧凑、对话干练、感官落地。

### Step 3: 一致性与逻辑审计 (Consistency Audit)
每章生成后，立即执行四项审计：
1. **战力与规则检查**：是否越级使用了未解锁的权柄？消耗与代价是否合规？
2. **伤病与记忆检查**：上一章受的伤是否在此章凭空消失？欠神债遗忘的记忆是否违规被主角想起？
3. **人设与动机检查**：行为是否符合人物一贯性格与生存哲学？有无无脑圣母或突兀降智？
4. **伏笔呼应检查**：本章埋下的伏笔或回收的暗线是否与台账一一对应？

### Step 4: 台账同步与新设定建档 (Ledger Sync & Lore Extraction)
- 将新出场的配角、地点、物品提取为标准条目，更新至 `lorebook/`。
- 将本章产生的新神债、新记忆损失、新伏笔编号记入《连续性台账.md》。
